## 2025-05-22 - [HIGH] Missing Authorization and BOLA on Blockchain Endpoints
**Vulnerability:** The `/api/blockchain/explore` and `/api/blockchain/claim/[id]` endpoints lacked authentication and authorization checks. This allowed any user (or unauthenticated attacker) to browse all blockchain claim events and fetch specific claim details. Furthermore, the claim detail endpoint was vulnerable to BOLA (Broken Object Level Authorization), as it didn't verify if the requester was the owner (patient), the involved hospital, or an auditor.
**Learning:** Security-critical endpoints that interact with external systems (like blockchain) were assumed to be "read-only" or "transparent" and thus overlooked during the initial authentication implementation phase.
**Prevention:** Always apply the Principle of Least Privilege. Every API endpoint must have an explicit authentication check and an authorization check (RBAC/ABAC). Centralize authorization helpers (like `canAccess`) to ensure consistency across different routes accessing the same data models.
